# NS-09: Mandatory Executive Summary in spec.md

> **Status:** In Progress  
> **Priority:** P1 — High (direct user feedback, immediate UX improvement)  
> **Created:** 2026-08-06  
> **Related:** User feedback on specs >300 lines, cognitive overload on review  
> **ADR:** [`ADR-014`](../decisions/ADR-014-executive-summary-in-spec.md)

---

## 🎯 Problem

### User feedback

- _"Existen specs de más de 300 líneas detalladas"_
- _"Se tiene que invertir mucho tiempo en entender toda la spec"_

### Root cause

`forge-arch` generates complete `spec.md` files without an executive summary. Users must read the entire document to understand what the feature does, what FRs it covers, and what decisions were made.

### Why this happens

The `spec.md` template in `skills/forge-arch/SKILL.md` mandates 5 sections (Objective, FR, NFR, PM, OQ) but does NOT mandate an executive summary at the top. forge-arch generates sections sequentially without a high-level overview.

### Impact

| Metric | Current | Expected after fix |
|--------|---------|-------------------|
| Time to understand a 300-line spec | 15-20 min | 2-3 min (summary) + optional deep read |
| Need to read full spec | Always | Only when detail is needed |
| CKP-1 review experience | Read everything, then approve | Read summary, approve or dig deeper |

---

## 📋 Scope

### In scope

1. **Modify `forge-arch` SKILL.md** to always generate an executive summary as the first section of `spec.md`
2. **Summary format**: 15-20 lines covering Objective, Scope, FRs table, Key decisions, Risks
3. **No changes to orchestrator** — the spec.md format is the same, just has a summary at the top
4. **No state management** — no `_spec_wip.md`, no resume, no conversational loop
5. **No IDE parity changes** — the summary is part of spec.md, which all IDEs already handle

### Out of scope

- Conversational mode (over-engineering for this problem)
- State persistence (_spec_wip.md)
- Resume capability
- Orchestrator changes
- Configurable summary length
